# HotspotFinder

[English](README.md) · **한국어**

PDB 복합체의 PPI 계면을 찾고, 단일 잔기의 alanine 변이에 따른 결합 변화를 로컬 계산 도구로 비교하는 연구용 앱입니다. 상단의 **한국어 / English** 버튼으로 표시 언어를 바꿀 수 있으며, 선택한 언어는 브라우저에 저장됩니다.

**[예제로 따라 하는 사용 가이드](docs/USER_GUIDE_KO.md)**

## 실행

저장소를 내려받은 뒤 프로젝트 폴더에서 다음 명령을 실행합니다. 처음 실행할 때는 Python 3(`venv`와 `pip` 포함), Node.js와 npm, 패키지를 내려받을 인터넷 연결이 필요합니다.

```sh
python3 scripts/launch.py
```

실행기는 프로젝트의 `.venv/`에 Python 패키지를 설치하고 첫 실행 시 웹 화면을 빌드합니다. 브라우저에서 [로컬 앱](http://127.0.0.1:8765/)을 열 수 있습니다. 종료하려면 실행한 터미널에서 Ctrl+C를 누르세요.

| 환경 | 실행 방법 |
| --- | --- |
| macOS | 위 명령을 실행하거나 [HotspotFinder.command](HotspotFinder.command)를 더블클릭합니다. |
| Linux | Linux 터미널에서 실행하고 CPU 아키텍처에 맞는 엔진 바이너리를 설치합니다. |
| Windows | WSL2의 Ubuntu 터미널에서 실행합니다. 엔진은 WSL2 안에 Linux용으로 설치하고 화면은 Windows 브라우저에서 엽니다. |

현재 설치부터 계산까지 검증된 플랫폼은 Apple Silicon 기반 macOS입니다. Linux와 WSL2는 실행 경로를 제공하며 전체 동작 검증은 남아 있습니다.

## 계산 도구 설치

앱의 **계산 엔진** 화면에서 설치합니다.

| 엔진 | 설치 방식 | 단일 알라닌 치환 점수 |
| --- | --- | --- |
| EvoEF 1.1 | 앱에서 지정 버전의 소스를 컴파일 | 짝지은 변이형과 야생형 구조의 `ComputeBinding` 점수 차이. EvoEF 고유 단위 사용 |
| FoldX | 운영체제에 맞는 공식 배포 파일 선택 | 선택한 파트너 간 `AnalyseComplex` 상호작용 에너지의 변이형–야생형 차이(kcal/mol) |
| Flex ddG | 실행 파일과 데이터베이스가 포함된 Rosetta 배포 파일 선택 | 변이형과 야생형에서 각각 계산한 결합 상태와 분리 상태의 점수 차이를 비교(REU) |
| SAAMBE-3D | CPU 전용 환경과 회귀 모델 자동 설치 | 복합체 구조로 예측한 결합 자유에너지 변화 ΔΔG(kcal/mol) |
| BudeAlaScan | Docker와 로컬 이미지 연결 | 스캔 원점수(kJ/mol)를 보존하고 4.184로 나눈 값(kcal/mol)도 표시 |

Flex ddG와 BudeAlaScan은 설치부터 실제 계산까지의 통합 검증이 남아 있습니다.

EvoEF 최초 설치에는 Git과 C++ 컴파일러가 필요합니다. macOS에서는 Xcode Command Line Tools, Linux/WSL에서는 build-essential을 사용합니다. 설치 소스 버전은 [버전 목록](third_party/sources.json)에 기록되어 있습니다. 기존 소스 캐시가 있으면 재사용합니다.

FoldX와 Rosetta는 본인의 이용 조건에 맞는 배포 파일을 공식 사이트에서 받은 뒤 앱에 선택합니다. 앱은 최대 8 GiB 압축 파일, 압축 해제 후 최대 20 GiB를 지원합니다. 현재 OS용 실행 파일이 포함되어야 합니다. 기존 설치와 더 큰 패키지는 고급 설정으로 연결할 수 있습니다. [FoldX 배포·이용 안내](https://foldxsuite.crg.eu/licensing-and-services) · [Rosetta 다운로드·이용 안내](https://rosettacommons.org/software/download/)

BudeAlaScan은 Docker와 SCWRL 등이 포함된 실행 이미지 준비가 필요합니다. 현재 버전에서 BudeAlaScan 이미지 빌드는 수동입니다. 고급 설정에 로컬 `sha256` 이미지 ID를 넣으면 네트워크를 끈 컨테이너로 시험합니다. 컨테이너의 실행 경로는 공식 standalone 설치의 `/root/bin/budeAlaScan.py`를 사용합니다. [공식 BAlaS 소스와 설치 안내](https://github.com/wells-wood-research/BAlaS)

설치와 시험 계산은 작업 화면에서 진행 상황·로그를 확인하고 취소하거나 재시도할 수 있습니다. 시험 계산을 통과하면 해당 도구가 활성화됩니다.

## 분석 흐름

1. PDB 파일을 불러오거나 [1JTG 예제](examples/1JTG_AB.pdb)를 엽니다.
2. 모델, 결합 파트너, 분석할 체인과 계면 거리 기준을 선택합니다.
3. 계면 후보를 검토하고 계산할 잔기와 준비된 도구를 선택합니다.
4. 기본 Heatmap에서 잔기를 선택해 서열과 3D 구조의 위치를 확인합니다. 표 보기로도 전환할 수 있습니다.
5. 선택 후보에 Flex ddG 후속 분석을 추가할 수 있습니다.
6. CSV 또는 원본·변환 구조·잔기 매핑·설정·로그·파일 해시가 포함된 ZIP을 저장합니다.

### 계면 정의와 잔기 매핑

계면 거리 기준은 기본 **5 Å**이며 2–12 Å 범위에서 조정할 수 있습니다. 분석 체인 잔기의 중원자 중 하나라도 상대 파트너의 중원자와 이 거리 이내에 있으면 계면 잔기로 분류합니다. 거리 열에는 조건을 만족하는 가장 가까운 원자 쌍의 거리를 표시합니다. 계산 가능한 계면 잔기는 기본 선택됩니다.

대체 위치(altloc)가 있는 잔기는 점유율 합이 가장 큰 배치를 선택하고 공통 원자를 유지합니다. 엔진 입력에는 정규화한 체인 ID와 잔기 번호를 사용합니다. 매핑에는 원본 모델·체인·잔기 번호·삽입 코드가 기록되며 번호 공백도 보존합니다. Ala는 스캔에서 제외하고 Gly는 선택적으로 포함합니다. 선택한 파트너에 지원되지 않는 보조인자·비표준 잔기 또는 주사슬 원자 누락이 있으면 먼저 구조를 정리해야 합니다.

### 점수 방향과 합의 판정

양수 점수는 알라닌 치환 시 결합이 약해질 것으로 예측한다는 뜻입니다. 엔진별로 판정 임계값과 근거를 지정합니다. 한 잔기에 적용 가능한 임계값과 완료 점수가 있는 엔진이 2개 이상이고, 그중 3분의 2 이상에서 점수가 각 임계값 이상이면 합의 후보로 표시합니다. 초기 임계값은 비어 있습니다.

## SAAMBE-3D로 비교하기

계산 엔진에서 **SAAMBE-3D → 자동 설치 및 검증**을 선택합니다. 앱이 전용 환경과 회귀 모델을 준비합니다. 처음 설치할 때 인터넷, Git 및 C/C++ 컴파일러가 필요합니다. 설치된 Conda를 사용할 수 있고, Conda와 micromamba가 모두 없으면 앱이 해당 플랫폼용 micromamba를 받아 해시를 확인합니다.

각 파트너에 체인을 하나씩 지정하고 계산 실행에서 SAAMBE-3D를 선택합니다. 선택 잔기 전체를 한 번에 처리하며 반복 수는 1입니다. 결과 해석에는 완료된 도구가 자동 선택되며, 기존 결과와 같은 잔기 집합에서 순위를 비교합니다. 점수는 예측 ΔΔG(kcal/mol)이며 양수는 결합 약화를 뜻합니다. 모델이 사용하는 실험 조건은 원본 PDB의 REMARK를 전달하며 누락된 값은 공식 코드의 기본 처리를 따릅니다. [공식 모델과 사용법](https://github.com/delphi001/SAAMBE-3D/tree/182a2746c8adb7434f1ac28c111e6b3f031c59e7)

## 결과 해석

계면 분석의 잔기 표 아래에서 완료 결과가 있는 모든 도구가 기본 선택됩니다. 체크박스로 비교 대상을 조정할 수 있습니다. 모든 선택 도구에서 최신 설정의 반복 계산이 완료된 잔기만 비교합니다. 제외 사유는 화면에서 펼쳐 볼 수 있습니다.

- 산점도에 도구별 원점수와 단위를 표시합니다. Spearman ρ는 공통 잔기의 순위 일치도를 나타냅니다. 도구를 세 개 이상 선택하면 순위상관 행렬도 표시합니다.
- 상위 후보 수 K를 바꾸면 공통 후보 목록과 Jaccard 지수(교집합 크기 / 합집합 크기)가 갱신됩니다. 경계의 동점은 모두 포함합니다.
- 잔기 우선순위는 도구별 내림차순 순위를 동일 비중으로 평균합니다. 순위 차이와 부호 불일치로 결과를 좁히고 잔기를 선택해 서열·구조·상세 정보를 확인할 수 있습니다.
- 임계값 민감도에서 양수 기준을 입력하면 기준 이상인 잔기 수와 목록을 미리 볼 수 있습니다. 판정 기준을 변경하려면 근거를 입력하고 저장합니다.
- 비교 결과 CSV에는 공통 잔기의 원본 번호, 도구별 점수·단위, 순위, 반복 수·표준편차 및 실행 설정 식별자가 포함됩니다.

## 작업 실행과 재현성

분석·작업·설치 파일은 `.hotspotfinder/`에 저장합니다. 브라우저 이동이나 새로고침 중에도 계산이 계속됩니다. 앱 종료 시 진행 중 작업은 중단되고, 비정상 종료 후에는 중단된 작업을 실패로 기록해 재시도할 수 있습니다. 기본 동시 작업 수는 1입니다.

설치에 필요한 파일을 준비한 뒤 계산·3D 시각화·내보내기는 로컬에서 동작합니다. Mol*와 화면 자산은 앱에 포함되어 있습니다. `HOTSPOT_DATA` 환경 변수로 저장 폴더를 바꿀 수 있습니다.

FastAPI 서비스와 별도 계산 프로세스가 로컬 SQLite 작업 대기열을 공유합니다. 각 잔기와 엔진에 대해 최신 실행 설정 및 반복 계획에서 성공한 계산을 집계합니다. 같은 반복 회차를 재시도하면 최신 시도가 이전 시도를 대체합니다. 성공한 반복의 평균을 표시하고, 2회 이상이면 표본 표준편차도 제공합니다.

내보낸 점수를 추적하려면 ZIP의 `residue_mapping.csv`에서 잔기 번호를 확인한 뒤 해당 작업의 `jobs/<job-id>/result.json`을 엽니다. 여기에는 엔진 설정과 식별 해시, 정규화 입력 구조의 해시, 반복 회차, 원시 출력값이 기록됩니다. `file_hashes.json`에는 ZIP에 담긴 작업 파일의 SHA-256 해시가 들어 있습니다.

실행기가 Python 환경을 준비한 뒤 자동 테스트를 실행합니다.

```sh
.venv/bin/pytest -q
```

```sh
.venv/bin/python scripts/smoke_local.py --install
```
