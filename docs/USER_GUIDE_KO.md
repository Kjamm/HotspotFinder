# HotspotFinder 사용 가이드

[English](USER_GUIDE.md) · **한국어** · [프로젝트 README](../README_KO.md)

처음에는 앱에 포함된 1JTG 복합체로 시작해 보세요. 앱을 열면 바로 계면 잔기를 찾고 3D 구조를 살펴볼 수 있습니다. 잔기별 예측 점수를 보려면 계산 엔진 하나를 설치해 실행하세요. 같은 잔기에 두 번째 엔진을 실행하면 도구 간 순위와 예측 방향도 비교할 수 있습니다.

## 1. 앱 실행하기

내려받은 프로젝트 폴더에서 아래 명령을 실행하세요. 처음 실행할 때는 Python 3와 `venv`·`pip`, Node.js와 npm, 인터넷 연결이 필요합니다. 실행 스크립트가 가상환경을 만들고 필요한 패키지를 설치한 뒤 화면을 빌드합니다.

```sh
python3 scripts/launch.py
```

실행한 터미널을 열어 두세요. 브라우저가 자동으로 열리지 않으면 [로컬 앱](http://127.0.0.1:8765/)에 접속하세요. 상단에서 **한국어**를 선택하면 이 가이드와 같은 메뉴명이 표시됩니다. 마지막으로 선택한 언어는 브라우저에 저장됩니다.

macOS에서는 `HotspotFinder.command`를 더블클릭해도 됩니다. Linux에서는 터미널에서 실행하세요. Windows에서는 WSL2의 Ubuntu 터미널에서 앱을 실행하고 엔진도 Ubuntu 안에 설치한 뒤 Windows 브라우저로 접속하세요. 현재 설치부터 분석까지 검증한 환경은 Apple Silicon Mac입니다.

## 2. 1JTG 예제로 첫 결과 얻기

1. **계면 분석 → 예제 불러오기**를 누르세요. **파트너 1**은 A, **파트너 2**는 B, **변이 대상 체인**은 A로 지정합니다. 이렇게 하면 B와 접촉하는 A의 잔기를 찾습니다.
2. 계면 cutoff를 **5 Å**로 두고 **계면 확인**을 누르세요. 서열, 3D 구조, 잔기별 히트맵이 나타납니다. 이 단계에서 확인할 수 있는 것은 접촉 위치이며, 각 엔진의 점수는 계산을 마치면 채워집니다.
3. **계산 엔진 → EvoEF → 자동 설치 및 검증**을 누르세요. EvoEF 설치에는 Git과 C++ 컴파일러가 필요합니다. **계산 작업**에서 설치와 예제 시험 계산의 진행 상황을 확인하세요. EvoEF 상태가 **실행 가능**이면 준비가 끝났습니다. 이미 실행 가능한 엔진이 있다면 그 엔진으로 진행해도 됩니다.
4. **최근 분석**에서 예제를 다시 여세요. 처음에는 계산 가능한 계면 잔기가 모두 체크되어 있습니다. 짧게 시험하려면 **잔기별 계산 결과**의 표 머리글 체크박스를 해제한 뒤 계산할 잔기 두세 개만 체크하세요. 잔기 이름을 클릭하면 3D 구조에서 위치를 확인할 수 있고, 왼쪽 체크박스로 계산 대상을 지정합니다.
5. **계산 실행**에서 EvoEF를 선택하고 **반복 수**를 1로 둔 뒤 **…개 잔기 계산**을 누르세요. **계산 작업**에서 완료를 확인한 뒤 분석 화면으로 돌아와 점수가 있는 잔기를 클릭하세요. 상세 영역에 점수, 단위, 실행 기록이 표시됩니다. 성공한 반복이 한 번이면 표준편차(SD)는 공란입니다.
6. 두 도구를 비교하려면 같은 잔기를 체크한 상태에서 다른 엔진을 선택해 실행하세요. **결과 해석**에서 두 엔진을 체크합니다. 두 엔진 모두 계산을 마친 잔기가 두 개 이상이면 평균 순위를 살펴볼 수 있습니다.

## 3. 내 PDB로 계면 설정하기

**PDB 불러오기**를 누르거나 업로드 영역에 `.pdb` 또는 `.ent` 파일을 놓으세요. 입력은 최대 20 MB의 PDB 형식입니다. mmCIF 구조라면 먼저 PDB로 내보내고, 변환된 파일에서 체인 ID를 확인하세요.

| 화면 항목 | 선택 방법 |
| --- | --- |
| 구조 모델 | 좌표를 분석할 모델 하나를 선택합니다. |
| 파트너 1 / 파트너 2 | 상호작용의 한쪽을 구성하는 체인을 각 그룹에 넣습니다. 양쪽 모두 한 개 이상의 체인이 필요하며, 같은 체인을 양쪽에 넣을 수 없습니다. |
| 변이 대상 체인 | 알라닌으로 치환해 볼 체인을 선택합니다. 양쪽 계면의 잔기를 모두 살펴보려면 두 파트너의 체인을 여기에 포함하세요. |
| 계면 cutoff (Å) | 기본값은 5 Å이며 2–12 Å에서 조절할 수 있습니다. 잔기의 중원자와 반대편 파트너 중원자 사이 거리가 이 값 이내이면 계면 잔기로 분류합니다. |
| Gly→Ala 포함 | 기본값은 해제입니다. 글리신에 곁사슬을 추가하는 치환까지 분석하려면 선택하세요. 원래 알라닌인 자리는 계산 대상에서 제외됩니다. |

**계면 확인** 후 **전체 잔기 / 수동 후보** 필터를 선택하면 거리 기준 밖에 있는 변이 대상 체인의 잔기도 직접 체크할 수 있습니다. 검색에는 `A:Y105`처럼 원본 PDB의 체인·잔기 표기를 사용하세요. 표 머리글 체크박스는 현재 보이는 계산 가능 잔기에만 적용됩니다. 검색이나 필터로 가려진 잔기도 체크되어 있을 수 있으므로 실행 전 **선택한 잔기** 필터로 대상을 확인하세요.

## 4. 엔진 선택과 작업 관리

| 엔진 | **계산 엔진** 화면에서 준비할 내용 | 실행 조건과 단위 |
| --- | --- | --- |
| EvoEF | **자동 설치 및 검증**을 선택합니다. 앱이 소스를 내려받아 로컬에서 컴파일합니다. | 결합 점수 변화량을 EvoEF 자체 단위로 표시합니다. |
| FoldX | 내 운영체제용 공식 배포 파일을 받은 뒤 **배포 파일로 설치**를 선택합니다. | 선택한 파트너 간 상호작용 에너지 변화량을 kcal/mol로 표시합니다. |
| SAAMBE-3D | **자동 설치 및 검증**으로 CPU 환경과 모델을 준비합니다. 최초 설치에는 인터넷, Git, 컴파일러가 필요합니다. | 파트너별 체인 한 개가 필요합니다. 선택한 잔기를 하나의 배치로 한 번 계산하며 예측 결합 ΔΔG를 kcal/mol로 표시합니다. |
| BudeAlaScan | SCWRL을 포함한 BudeAlaScan 이미지를 로컬에 준비합니다. **고급 설정**에 Docker 실행 경로와 로컬 이미지 ID를 입력해 저장하고 시험 계산을 실행합니다. | 반복 수를 1로 설정하세요. 원래 단위인 kJ/mol 점수를 kcal/mol로 환산해 표시합니다. |
| Flex ddG | 실행 파일과 데이터베이스가 들어 있는 Rosetta 배포 파일로 설치합니다. | 잔기를 체크한 뒤 별도의 **Flex ddG 후속 분석** 영역에서 실행합니다. 기본 ensemble 수는 35이며 점수 단위는 REU입니다. |

이미 설치한 엔진은 고급 설정에 실행 파일의 절대 경로와 필요한 데이터 폴더 또는 이미지 ID를 입력해 연결할 수 있습니다. 설정을 저장하고 시험 계산을 실행하세요. **실행 가능**은 앱이 예제 입력을 처리하고 해당 엔진의 출력을 읽는 데 성공했다는 뜻입니다. Flex ddG와 BudeAlaScan은 아직 설치부터 결과 확인까지의 검증이 남아 있습니다. [설치 세부 사항과 공식 배포처](../README_KO.md#계산-도구-설치)

기본값은 한 번에 작업 한 개입니다. **계산 엔진 → 동시 작업 수**로 동시 실행 개수를 바꾸고, 분석 화면의 **작업 제한 (초)**에서 작업당 제한 시간을 지정할 수 있습니다. SAAMBE-3D를 선택하면 기본 계산 전체의 반복 수가 1로 고정됩니다. BudeAlaScan은 반복 수를 직접 1로 설정하세요. 다른 엔진을 여러 번 반복하려면 별도 작업으로 제출하세요. 로컬 서비스가 실행 중이면 브라우저를 닫아도 계산은 계속됩니다. 실패한 작업은 **계산 작업 → 로그**에서 원인을 확인하고 해결한 뒤 재시도하세요. 앱을 종료할 때는 작업 완료 후 실행 터미널에서 Ctrl+C를 누르세요.

## 5. 점수와 합의 후보 읽기

- **히트맵과 표.** 양수는 알라닌 치환 후 결합이 약해진다는 예측입니다. 대시(—)는 결과가 없는 칸입니다. 각 엔진 열에 표시된 단위를 보고 같은 열 안에서 잔기를 비교하세요. 색을 빼고 수치만 읽으려면 **표**를 선택하세요. `2/3`은 계획한 세 번 중 두 번이 끝났다는 뜻입니다. 표시값은 성공한 반복의 평균이며, 두 번 이상 성공하면 표본 표준편차(SD)도 표시됩니다.
- **결과 해석.** 비교할 엔진을 체크하세요. 선택한 모든 엔진에서 최신 설정의 반복 계산을 전부 마친 잔기만 비교에 들어갑니다. 예상보다 적으면 **분석 대상 및 제외 사유**를 펼치세요. Spearman ρ는 엔진 간 순위 일치도를 나타냅니다. 상위 K개 후보에는 경계에서 동점인 잔기도 포함되며, Jaccard 지수는 교집합 크기를 합집합 크기로 나눈 값입니다. 평균 순위가 작을수록 여러 도구에서 상위에 놓인 잔기입니다. 순위 차이가 크면 어떤 도구에서 예측이 갈렸는지 살펴보세요.
- **합의 판정 기준.** 엔진 결과가 나온 뒤 해당 단위의 양수 임계값과 그 근거가 되는 평가 데이터·문헌·프로토콜을 입력하세요. **임계값 민감도**에서는 기준을 넘는 잔기 수를 미리 볼 수 있고, **기준 저장**을 눌러야 합의 판정에 적용됩니다. **합의 판정** 열의 세 숫자는 ‘지지한 엔진 수 / 판정에 참여한 엔진 수 / 해당 잔기에 작업이 등록된 엔진 수’입니다. 예를 들어 `2 / 3 / 4`는 판정에 참여한 세 엔진 중 두 엔진이 지지해 합의 조건을 충족합니다. 판정에 참여한 엔진이 최소 두 개이고, 그중 3분의 2 이상이 지지해야 합의 후보가 됩니다. 임계값을 비워 둔 엔진은 점수만 표시합니다. 합의 후보는 후속 실험으로 확인할 예측 결과입니다.

## 6. 결과 내보내기와 다시 열기

| 화면에서 선택할 항목 | 파일 내용 |
| --- | --- |
| **잔기별 계산 결과 → CSV** | `hotspots.csv`. 잔기·엔진별로 점수, 단위, 반복 수, 상태, 임계값 충족 여부를 기록합니다. 점수가 없는 엔진의 행도 포함됩니다. |
| **결과 해석 → 비교 결과 CSV** | 현재 비교 대상으로 선택한 엔진의 공통 완료 잔기, 순위, SD, 설정 식별값을 담습니다. 비교할 공통 결과가 있을 때 링크가 나타납니다. |
| **잔기별 계산 결과 → 전체 기록** | 원본·정규화 PDB, 잔기 매핑, 분석 설정, 결과와 작업별 로그·출력 파일을 ZIP으로 받습니다. |

점수를 원본 구조와 대조하려면 `residue_mapping.csv`에서 원본 체인, 잔기 번호, 삽입 코드가 일치하는 행을 찾으세요. 같은 행의 엔진용 체인과 번호를 확인한 뒤 해당 작업의 `jobs/<job-id>/result.json`을 열면 계산 내용을 추적할 수 있습니다. 기존 분석은 **최근 분석**에서 다시 열 수 있습니다. 기본 데이터 저장 위치는 프로젝트 아래의 `.hotspotfinder/`입니다.

## 문제 해결

| 증상 | 확인할 내용 |
| --- | --- |
| 계산 버튼이 비활성화됩니다. | 계산 가능한 잔기와 실행 가능한 엔진이 각각 하나 이상 선택됐는지 확인하세요. SAAMBE-3D라면 파트너별 체인이 한 개인지도 확인하세요. |
| 계면 잔기가 보이지 않습니다. | 검색과 필터를 해제하세요. 선택한 모델·파트너·변이 대상 체인, 거리 기준을 확인하고 구조에서 두 체인이 실제로 접촉하는지 살펴보세요. |
| 주사슬 원자 누락이나 미지원 보조인자 메시지가 뜹니다. | 구조 전처리 기록을 펼쳐 원본 PDB와 대조하세요. 지원 가능한 구조를 준비한 뒤 새 분석으로 불러오세요. 앱은 원본 번호의 공백을 보존하며 결손 루프를 모델링하지 않습니다. |
| 히트맵에 점수가 있는데 비교 결과나 합의 후보가 비어 있습니다. | 반복이 전부 끝났는지, 같은 잔기를 계산했는지, 엔진 설정을 바꿨는지 확인하세요. 합의 판정은 현재 설정에 적용되는 임계값이 저장된 엔진도 최소 두 개 필요합니다. |
